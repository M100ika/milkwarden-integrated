# Архитектура интеллектуального модуля Milkwarden

Документ описывает актуальную архитектуру мониторингового модуля для молокодоильных установок. Система состоит из распределённых сенсорных узлов, коммуникационного шлюза и серверной части, которые работают согласованно и не требуют модификации механического оборудования.

---

## 1. Цели и проектные принципы
- **Непрерывный сбор данных.** Все параметры процесса доения (вес, поток, вакуум, температура, мутность, электропроводность) измеряются с частотой 1–5 Гц и сохраняются в виде временных рядов.
- **Модульность.** Каждый слой (сенсоры, связь, сервер) заменяем без переработки других слоёв. Для периферии применяются стандартные шины UART/SPI/I2C.
- **Кибербезопасность.** Устройства используют TLS 1.3, аппаратные ключи и взаимную аутентификацию. Конфигурации подписываются сервером и распространяются через защищённые каналы.
- **Надёжность.** Собственные буферы на Raspberry Pi и ESP32 сглаживают потери связи, а сервер хранит данные в PostgreSQL/TimescaleDB с репликацией и резервными копиями.

## 2. Компоненты и их роли

| Слой | Компонент | Назначение |
|------|-----------|------------|
| Сенсорный | ESP32-S3 узлы | Термометры (DS18B20), турбидность (SEN0189), TDS Meter V1.0, вакуум (0…−100 kPa), влажность корпуса (SHT31/BME280) |
| Сенсорный | Arduino Pro / ESP32-C3 + AD7797 | Управляет тензодатчиками веса, обеспечивает гальваническую развязку и 24-битное измерение |
| Сенсорный | Модуль опрыскивания | Форсунки с дезинфицирующим раствором, управляемые по GPIO; контролируются по рецептам и сценариям доения |
| Коммуникационный | Raspberry Pi Zero 2 W | Центральный шлюз, локальный брокер MQTT, буфер телеметрии, интерфейс с дисплеями Nextion и OLED |
| Коммуникационный | GSM-модем SIM7600 | Резервный uplink по HTTPS/MQTT при отсутствии Wi-Fi/Ethernet |
| Идентификация | CF-MU904 + RFID-антенны | Считывание EPC-меток 865–868 МГц |
| Идентификация | Jetson Orin Nano + PoE камеры | Машинное зрение, face-ID коров, сверка с RFID |
| Отображение | Nextion NX8048P050-011C и OLED | Отображение статуса установки и параметров по каждой корове |
| Серверный | Linux сервер + FastAPI/Django | Приём данных, API, аналитика, интеграция с PostgreSQL |
| Хранилище | PostgreSQL/TimescaleDB | Таймсерии `sensor_data`, каталоги `cow`, `milking_session`, события `device_logs` |

## 3. Логические контуры

### 3.1. Контур измерений
Тензодатчики соединены мостовой схемой и подключены к AD7797 через дифференциальные входы. Между сенсором и микроконтроллером установлена гальваническая развязка (ADuM). ESP32-S3 обслуживает аналого-цифровые датчики мутности и TDS, формируя батчи измерений и нормализуя единицы. Все значения приводятся к единому времени (NTP) и снабжаются метаданными (идентификатор коровы, пост, ревизия калибровки).

### 3.2. Контур идентификации
RFID и машинное зрение работают параллельно. При входе животного в пост сначала считывается метка EPC, затем камеры формируют эмбеддинг и сверяют его в каталоге PostgreSQL. Алгоритм использует правило majority: совпадение ≥2 систем переводит пост в режим доения, иначе система запрашивает подтверждение оператора на панели Nextion.

### 3.3. Контур гигиенической обработки
Система опрыскивания расположена в посту доения и управляется Raspberry через ESP32. После успешной идентификации Raspberry отправляет команду на исполнительный модуль, который включает форсунки на заданный интервал (например, 3–5 секунд). Срабатывание сопровождается датчиком давления и датчиком наличия коровы, чтобы исключить ложные срабатывания. Данные о каждой операции записываются в `hygiene_log`, что позволяет отслеживать соблюдение протоколов подготовки к доению.

### 3.3. Контур связи
ESP32 публикует телеметрию в локальный брокер Mosquitto на Raspberry (`milkwarden/<device_id>/telemetry`). Raspberry аггрегирует сообщения, подписывает их ключом Ed25519 и отправляет на сервер через REST (`POST /api/v1/telemetry`) или MQTT поверх TLS. При обрыве сети данные складываются в SQLite-журнал и выгружаются батчами после восстановления.

### 3.4. Контур визуализации
Локальные дисплеи получают данные по I2C и показывают метрики с частотой 1 Гц. Сервер строит графики и уведомления; браузерные клиенты подключаются по WebSocket к FastAPI, чтобы получать обновления в режиме реального времени. Jetson отправляет на сервер фотофрагменты для обучения и журналирует события распознавания в `vision_matches`.

## 4. Потоки данных

```
[Тензодатчики]--SPI-->[ESP32-C3+AD7797]--UART-->[Raspberry Pi]--TLS-->[FastAPI API]--SQL-->[PostgreSQL]
[Сенсоры качества]--I2C-->[ESP32-S3]--Wi-Fi MQTT-->[Raspberry Pi]
[RFID/Jetson]----> [Raspberry Pi] ----> [Server Alerts / UI]
```

Последовательность сессии доения:
1. CF-MU904 генерирует `rfid_event`, Raspberry связывает событие с ожидаемой коровой.
2. Jetson подтверждает личность и отправляет `vision_match`.
3. Raspberry выдаёт команду ESP32 начать запись сенсоров, AD7797 входит в режим 5 Гц.
4. Каждые 2 с публикуется телеметрия; раз в минуту Raspberry отправляет агрегированный отчёт на сервер.
5. После завершения сессии формируется запись `milking_session`, вычисляются показатели (надой, средний вакуум, индекс чистоты).
6. По завершении цикла доения форсунки опрыскивания переходят в режим промывки и готовности к следующему животному.

## 5. Серверная архитектура
- **API слой.** FastAPI (Uvicorn+Gunicorn) предоставляет REST и WebSocket. Используются pydantic-схемы для валидации и OpenAPI 3.1 для документации.
- **Persistence.** PostgreSQL с расширением TimescaleDB. Таблица `sensor_data` партиционируется по времени и `device_id`, `device_logs` хранит системные сообщения, `alerts` — критические события.
- **Аналитика.** Фоновые задачи (Celery/APScheduler) рассчитывают производные метрики, уведомления и отчёты. Prometheus собирает метрики, Grafana визуализирует здоровье системы.
- **Безопасность.** OAuth2/JWT для операторов, mutual TLS и ключи Ed25519 для устройств. Ротация сертификатов происходит через Ansible, конфигурации версионируются в GitOps-репозитории.

---

## 6. Надёжность и обслуживание
- Все узлы ведут локальные журнал-файлы (binary protobuf) и могут выгружать их вручную через USB.
- Конфигурации датчиков (диапазоны, коэффициенты фильтрации) хранятся в `calibration_profile` и передаются на устройства в виде подписанных JSON.
- Резервное питание реализовано парой MeanWell 24 В + DC-DC 5/3,3 В и аккумуляторным модулем LiFePO4; автономность до 2 часов.
- Обновления прошивок ESP32 выполняются по OTA через HTTPS; Raspberry и Jetson получают контейнеры через OCI-реестр.
